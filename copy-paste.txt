### 1. What Is Now There & Current Whitelist
Right now, the repository is a **single-agent Customer Support Prototype** ([`src/agent.py`](file:///d:/my%20TRY/Noir-Atelier/src/agent.py), [`src/llm_agent.py`](file:///d:/my%20TRY/Noir-Atelier/src/llm_agent.py), [`src/data_store.py`](file:///d:/my%20TRY/Noir-Atelier/src/data_store.py)) backed by local SQLite (`data/noir_atelier.db`).

* **Current Tool Whitelist ([`ALLOWED_TOOLS` in `src/llm_agent.py`](file:///d:/my%20TRY/Noir-Atelier/src/llm_agent.py#L18-L24)):**
  1. `lookup_products(query)`
  2. `lookup_policies(topic)`
  3. `get_order_status(order_id, customer_email)`
  4. `process_return_or_cancel(order_id, customer_email, action, reason, request_key)`
  5. `escalate_to_human(reason, category, severity, order_id, customer_email)`
* **Current Gate & Security Whitelist ([`ToolPolicyGate`](file:///d:/my%20TRY/Noir-Atelier/src/llm_agent.py#L85-L120) & [`src/guardrails.py`](file:///d:/my%20TRY/Noir-Atelier/src/guardrails.py)):**
  * **Identity Whitelist:** `order_id`, `customer_email`, and `request_key` cannot be guessed by the LLM—they must be extracted directly from the customer's message (`CustomerFacts`).
  * **Action Whitelist:** Only `"return"` and `"cancel"` are allowed when explicitly requested by the customer; exchange requests are forced to escalate.
  * **Turn & Session Caps:** Max `1` mutation and `1` escalation per turn; session locks after `3` failed verification attempts.
  * **PII Scrubber:** Replies only allow emails/phones/addresses belonging to `verified_emails`.

### 3. What We Follow (Confirmed Stack & Short-ID Local Object Storage)

1. **Databases We Follow:**
   * **PostgreSQL 16+**: Source of truth for all transactional data + `JSONB` for flexible attributes + Full-Text Search (`tsvector`/`GIN`) for Phase 1–2 (replacing the need for MongoDB, and deferring Elasticsearch until >10K products).
   * **Redis**: Ephemeral state for carts, sessions, rate-limiting, and inventory caching.
   * **Qdrant**: Self-hosted Vector DB for semantic style search and recommendations.
2. **Local Object Storage (`./storage/`) with Short, Understandable IDs (6–10 chars max):**
   * `storage/products/PRD-001/` → `main.jpg`, `back.jpg`, `size-chart.png`, `meta.json`
   * `storage/orders/ORD-1001/` → `INV-1001.json`, `INV-1001.txt` (GST Tax Invoice), `SHP-3001-label.txt` (AWB label)
   * `storage/payments/PAY-5001/` → `receipt-ORD-1001.json`
   * `storage/returns/RET-8802/` → `defect-photo-1.jpg`, `inspection-note.json`
   * `storage/support/ESC-9001/` → `transcript-ORD-1001.json`
   * `storage/compliance/POL-RET-01/` → `approval-cert.json`
